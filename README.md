# Raindrop of the Month

One-page monthly showcase of a single private company, produced by Rainmaker Securities.
Each month lives in its own folder. The page is an HTML file with local assets that prints to
exactly one US Letter page and uses readable responsive text with a scrolling middle section and always-visible navy header and trade bar.

## Folder layout

```
Raindrops/
├── README.md              <- this file
├── CLAUDE.md              <- rules for Claude when working in this project
├── render.sh              <- rebuilds the page from content.md, then the PDF + preview; checks it is one page
├── build.py               <- turns content.md into raindrop.html (run by render.sh)
├── template.html          <- the design: CSS and layout shared by every month (rarely edited)
├── inline.py              <- builds the standalone share copy (run by render.sh)
├── publish.sh             <- commits and pushes; the GitHub Action then renders and deploys the site
├── stage.sh               <- assembles site/ (what gets deployed) from the rendered months
├── .github/workflows/     <- the Action: renders every month and publishes on every push
├── site/                  <- generated website folder (not committed)
├── brand/                 <- shared Rainmaker logos (reused every month)
│   ├── rainmaker_logo_color.webp   navy wordmark + gold R, for white backgrounds
│   └── rainmaker_logo_dark.png     white wordmark + gold R, for navy backgrounds
└── 2026-10-anduril/       <- one folder per issue: YYYY-MM-company
    ├── content.md         <- THE FILE YOU EDIT: all the words, in plain text
    ├── raindrop.html      <- generated from content.md by render.sh (do not edit by hand)
    ├── raindrop.pdf       <- generated by render.sh (do not edit by hand)
    ├── preview.png        <- generated by render.sh
    ├── assets/            <- company logo + photos used by raindrop.html
    └── archive/           <- earlier takes of this issue, kept for reference only
```

## Editing an issue

**From the browser (no tools needed).** Open the live page with `?edit=1` on the end, for example
https://benmartinrainmaker.github.io/rainmaker-raindrop/2026-10-anduril/?edit=1 . Every piece of
text gets a dashed outline: click it, type, press Enter or click elsewhere when done. Cmd+B and
Cmd+I bold and italicize. Then press **Save & publish**. The first time, enter your name and the
editing key (Ben has it); it stays in that browser. The save writes `content.md` into the GitHub
repo and the page rebuilds itself in about two minutes. If the Save complains that someone else
changed the text, reload the page and redo the edit. **Download content.md** gives you the edited
file instead, for sending to Ben. Photos, the chart, and the logos are not editable this way.

**From a text editor or an AI tool.** Clone the repo (https://github.com/BenMartinRainmaker/rainmaker-raindrop),
edit `content.md`, and push to `main`; the Action publishes. Locally, `./render.sh <folder>`
rebuilds the page and PDF so you can check the one-page limit before pushing, and `./publish.sh`
commits and pushes everything.

All the words live in `content.md`. Open it in any text editor (TextEdit, VS Code, Notes), change
the text, save, then run `./render.sh <folder>`. The page, PDF, and share files are rebuilt.
You never touch `raindrop.html`; the design lives in `template.html` and is shared by every month.

How `content.md` is laid out:

- The first lines are settings: `company:`, `month:` (e.g. `November 2026`), `subtitle:`,
  `logo in drop:` (transparent navy PNG), and `wordmark:` (optional; leave it out to show the
  company name as text instead of a logo).
- Every `# Heading` starts a section. Keep the section names as they are; the builder looks for
  them. Sections: Market note (optional), Introduction, Quote (optional), Tags, Key numbers,
  Photos, Valuation history (optional), What they build, Customers, Feature band, Timeline,
  Footer, Fine print.
- Paragraph sections (Market note, Introduction, Feature band, Footer, Fine print): just type.
  A blank line starts a new paragraph.
- List sections (Tags, Customers, product bullets): one item per line starting with `- `.
  `Name: phrase` makes the name bold automatically.
- Table sections use `|` between columns:
  - Key numbers: `$110B | Valuation | note under it`
  - Photos: `assets/file.jpg | alt text | caption | 50% 40%` (last column optional; shifts the crop)
  - Valuation history: `2024 | Series F | 14 | source url`; `reported: 110 | url | note` adds the
    dashed unconfirmed target; `caption:` is the small print under the chart. Axis scales itself.
  - Timeline: `March | what happened`. Four rows fit the print page; other counts still work.
- What they build: each `## Category name (icon)` starts a box with its bullets under it. Icons:
  aircraft, missile, sensor, shield, underwater, soldier, rocket, chip, cloud, building, factory,
  globe, car, satellite, bolt, dollar, heart, network, box.
- Formatting inside any text: `**bold**`, `*italic*`, `[link text](https://...)`. Straight quotes
  and apostrophes become curly ones. The `&` sign and `<` are safe to type as-is.
- `title:` on the first line of a section renames its heading (e.g. `title: 2027 so far`).

Keep text roughly the same length as what is there. The print page has about a quarter inch of
slack; `render.sh` warns if the PDF spills onto a second page. If it does, trim a bullet or two.

If you need something the content file cannot express (a new section, a layout change), that is
a `template.html` or `build.py` change. Ask Claude.

## Rendering the PDF and preview

```
./render.sh 2026-10-anduril
```

This rebuilds `raindrop.html` from `content.md`, then writes `raindrop.pdf` and `preview.png`
into the folder and warns if the PDF spills past one page. You can also open `raindrop.html` in Chrome and press Cmd+P (set margins to None,
turn on background graphics). The carousel arrows and dots are hidden automatically in print.

## Publishing

Every push to `main` runs the GitHub Action (`.github/workflows/publish.yml`): it renders every
month folder with headless Chrome, stages `site/` with `stage.sh` (noindex tag, version-stamped
image URLs, root redirect to the newest month), and deploys to GitHub Pages at
https://benmartinrainmaker.github.io/rainmaker-raindrop/<folder>/ . Web-editor saves push the same
way. A month that spills onto a second printed page still publishes, with a warning in the run log.
`./publish.sh "message"` is the local shortcut: pull, commit everything, push. The generated files
(`raindrop.html`, PDF, preview, `share/`, `site/`) are not committed; the Action regenerates them.

The editing key is a GitHub fine-grained personal access token on the Rainmaker account limited to
this repository with Contents read and write. Create it at
https://github.com/settings/personal-access-tokens/new , give it a long expiry, and share it with
the editors privately. Revoking it there locks everyone out at once.

## Starting a new month

1. Copy the most recent folder and rename it, e.g. `cp -r 2026-10-anduril 2026-11-lambda`.
2. Delete the `archive/` folder inside the copy and clear out `assets/` except for anything you reuse.
3. Drop in the new company's logo (transparent PNG, recolored to navy `#10305f`) and photos.
4. Edit `content.md` section by section (see "Editing an issue").
5. Run `./render.sh 2026-11-lambda` and open `preview.png`.

## Photos and licensing

Only use images you have the right to publish. Reliable sources:
- U.S. military photos are public domain. Search Wikimedia Commons with the company or product name.
- Creative Commons photos are fine if the photographer is credited in the caption and the disclaimer.
- Company press images are copyrighted. Ask the company's press office or skip them.

## Design rules (short version)

- White or light rain-blue background, deepest navy `#061530` for the company name and big numbers, gold for accents only.
- Font is Jost, loaded from Google Fonts. Works offline with the system fallback.
- Tags are all the same plain white style.
- No opinions. Rainmaker presents and brokers; it does not recommend. No bull or bear cases, no price targets.
- Dry, professional tone. One light touch of humor at most.
- Facts come from public reporting and are dated. Rumored rounds are labeled unconfirmed.
